# VINTAGE ALARM — Editorial durability guardrails

更新日: 2026-09-15

## 目的

VINTAGE ALARMは記事数や検索面の占有率を増やすことを最終目的にしない。

優先するのは、公開済みの少数のWATCHを、10年後でも実機・操作・音・機構・資料差へ辿れる形に保つこと。

**量を増やすより、時間に耐える形にする。**

## 1. 多言語版

- 日本語本文を正本とする。
- 公開済みEN / DEに同じ事実が存在する場合、事実訂正は同一変更単位で同期する。
- 翻訳深度がFULL / CONCISEで異なることは許容するが、公開済み翻訳に古い事実が残ることは許容しない。
- 詳細は `strategy/localization-sync.md` とCIの `check:localization-sync` / `check:localization-coverage` を正本とする。

## 2. SPECは軽く監査する

SPECを別DBへ拡張しない。全項目に `文献値` / `n=1` / `同型資料` 等のタグを付ける運用もしない。

ただし、掲載個体について未確認の値を同型資料から置く場合、または既知の資料差・内部矛盾がある場合は、必要な項目だけ限定して出所の範囲を明示する。

最初の回帰対象はCitizen Alarm。

- 37 mm / Citizen 980 / 17石 / 18,000振動は現在 `同型資料` と明示。
- 17石と本文の記述を一致させ、19石の旧矛盾を復活させない。
- 対象は `src/data/spec-evidence-audit.json` と `check:spec-evidence` で限定管理する。

## 3. 一次資料と再録一次資料

一次資料そのものと、専門書等に再録された一次資料を同じ取得状態として見せない。

例:

- Pierce AGの1955年技術資料そのものを直接確認した場合: `PRIMARY SOURCE`
- Beitl収録ページを通してPierce AG 1955技術資料を確認した場合: `PRIMARY SOURCE · REPRODUCED`

史料の内容上の一次性と、VINTAGE ALARMがどの媒体を通して確認したかを分ける。

## 4. 訂正・追加資料の入口

外部からの訂正は歓迎するが、外部から来た情報を自動的に正しいと扱わない。

WATCHの参考資料欄から次へ到達できるようにする。

- X `@rimacroissant`
- GitHub `Research correction / source difference` form

対象:

- 誤り候補
- 別個体・バリエーション
- 資料差
- 追加の一次資料・専門資料
- 実機観察

外部掲載・著名サイトからの指摘・専門家の肩書き自体は、内容の正確性保証として逆輸入しない。

## 5. 外部専門家との接続

外部接続の目的は権威付けや被リンク本数ではない。

相手側の不足を埋める資料・データ・実機観察を先に提供し、検索・DB・Wiki・記事・研究媒体・AIのどこから入っても証拠へ進める経路を増やす。

詳細は `strategy/external-reference-outreach.md` を正本とする。

## 6. AIの扱い

AIは調査補助、差分確認、翻訳監査、コード検証、検索設計など裏側で徹底利用してよい。

ただし:

- AIの出力自体を史実の根拠にしない。
- `AIが検証した`、`AI監査済み` 等をWATCH本文の品質ラベルにしない。
- 公開記事では、読者が確認できる資料、実機、写真、音、計測、資料差を前面に出す。
- AI利用の透明性はGitHubの運用履歴・方針で担保し、記事本文へ宣伝文句として持ち込まない。

## 7. SEO / AIOを目的化しない

以下を行わない。

- ブランド一覧の大量生成
- Calibre DB量産
- FAQ大量生成
- 検索語だけを差し替えた `○○とは` ページ量産
- AIOのためだけの本文分割・言い換え

新しいWATCH / 研究ページを作る条件は、少なくとも次のどちらかを満たすこと。

1. 所有・観察できる実機があり、既存ページでは代替できない情報がある。
2. 独立した研究論点と根拠資料があり、既存ページに押し込むより分ける方が読者の検証に有益。

検索で当たることを理由に記事数を増やさない。

## 8. 記事の濃度を揃えない

時計ごとに資料量・実機観察・研究論点が違うことを正常状態とする。

- 10WAはキャリバー系譜・特許比較が中心になり得る。
- Westcloxは文献値と掲載個体実測の差が中心になり得る。
- Citizenはメーカー公式資料で十分な箇所を無理に膨らませない。

テンプレートの空欄を埋めるためだけにDEEP DIVEを増やさない。

## 9. 作者の思想を証拠層と分ける

編集的な比喩・現代的な入口・作者の視点はOWNER'S NOTE、コピー、EPILOGUE等へ置ける。

HISTORY / DEEP DIVEの技術史・事実記述へ、思想やオチを根拠なしに混ぜない。

とくにSMARTWATCH批評はEPILOGUE側へ隔離し、機械式アラーム腕時計との直接系譜として断定しない。

## 10. 長期保存

X / YouTubeは配信・発見の入口であり、唯一の保存先にはしない。

重要な実機鳴動、機構動画、実測の証拠メディアについては、可能な限り元ファイルまたは高品質な保存用コピーを保持する。

運用:

- 外部投稿URLは公開導線として残す。
- 元ファイルの保存有無を内部で把握する。
- Xのみ、YouTubeのみで失われると検証不能になる証拠を増やさない。
- サイトで直接配信するか、別の長期保管先を使うかは容量・著作権・運用負荷を見て別途決める。
- 他者提供画像・動画は、提供条件を無視してローカル再配布しない。

現時点では、外部動画の元ファイル保存状態をrepoだけから確認できないため、**保存済みとは扱わない**。次回メディア追加時から保存状態を記録する。

## 成功状態

成功は「記事が増えた」「リンクが増えた」「AIに引用された」ではない。

- 既知の誤りが修正履歴とともに直る。
- 翻訳版へ同じ訂正が届く。
- 読者が資料・実機・音・機構へ遡れる。
- 外部から新しい証拠が入る経路がある。
- 外部サービスが消えても重要証拠を失いにくい。
- 時計ごとの情報密度を無理に均一化しない。

少数のWATCHでも、調べる人が長期に使える状態を優先する。
