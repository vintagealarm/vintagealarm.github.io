# VINTAGE ALARM — Evidence-led discovery / rabbit-hole operating plan

更新日: 2026-09-24

> **内部運用メモ。**
> rabbit hole は外向けの宣伝コピーではない。VINTAGE ALARMを有名にする意味でもない。
> **興味を持った人へ、その瞬間に合う具体的な時計を渡し、実機・音・操作・機構・資料へ自然に深く潜れる状態**を指す内部略称。

## 0. この作戦を一枚で言うと

VINTAGE ALARMは、不特定多数へサイトを売り込むのではなく、**すでに隣接する興味を持っている人を逃さない**。

基本の流れはこれ。

**興味・違和感**
→ **#勝手にキャッチコピーで現代語へ翻訳**
→ **その興味に合う具体的な1本を提示**
→ **OWNER'S NOTEで実機の体験へ接続**
→ **音・操作・DEEP DIVE / SOURCESで根拠へ沈む**
→ **関連WATCH / HOW THEY RING / HISTORY / 外部資料へ進む**
→ 必要なら**調査協力者・資料提供者になる**

目的はPVでも知名度でも被リンク数でもない。

**欲しい人に、欲しい時に、具体例を渡して、証拠のある沼へ案内する。**

外部参照施策の正本は strategy/external-reference-outreach.md、計測定義は measurement/metrics.md、実測結果は measurement/experiment-log.md とする。この文書へ短期のアクセス数や投稿結果は重複保存しない。

## 1. 外向けの原則 — サイトを売らず、時計を渡す

外へ出す主語はVINTAGE ALARMではなく、**時計・現象・実機観察・資料**にする。

### やる

- 「なぜこうなっている？」という現象を出す
- 相手の興味に合う具体的な時計を1本だけ出す
- 実機写真・音・操作・資料など、続きを確認できる材料を出す
- URLは、その材料をまとめて確認する必要がある時だけ添える
- 未確認事項は未確認のまま出し、情報提供を具体的に募集する

### やらない

- 「VINTAGE ALARMというサイトを作りました」を主語にした宣伝
- 文脈のないURL投下
- 関係の薄いスレッドへの便乗
- 定型文の大量投稿
- 「リンクしてください」から始める営業
- 相互リンク営業
- AI / SEO / AIOを営業文句にする
- サイト知名度、フォロワー、被リンク数を目的化する
- 興味のない相手を説得して引き込む
- 外部掲載を権威付けとして逆輸入する

**売るのはVINTAGE ALARMではなく、時計に残っている違和感・実機観察・未解決の問い・資料。**

## 2. VAの3層 — 現代翻訳 / 実機接続 / 証拠

VINTAGE ALARMの文章は、全部を同じ役割にしない。

### 入口 — #勝手にキャッチコピー

古い機械を、現代の感覚で一瞬で理解できる問い・比喩へ翻訳する。

役割:
- 「何が変なのか」を数秒で掴ませる
- モデル名を知らない人にも接点を作る
- 今の生活・通知・プロダクト感覚との橋を作る

例:
- 1950年代のマナーモード
- 身につける通知
- クロノメーターなのにアラーム
- 腕時計に見えるが、中身は別物

これらは**史実そのものではなく、史実へ入るための現代語の入口**。

### 接続 — OWNER'S NOTE

キャッチコピーで生じた「何それ？」を、所有実機へ接続する。

役割:
- 実際に持つ、触る、巻く、鳴らす視点を出す
- キャッチコピーの違和感を具体的な操作・音・造形へ戻す
- 読者を「面白いコピー」だけで終わらせない

### 根拠 — DEEP DIVE / SOURCES

ここで年代、機構、資料差、一次資料、専門資料、実測を確認する。

役割:
- キャッチやOWNER'S NOTEの背景を検証可能にする
- 資料間の差や未確認事項を隠さない
- VINTAGE ALARM自身の説明だけを根拠にしない

したがって基本構造は、

**現代語の違和感 → OWNER'S NOTE → 実機 / 音 / 操作 → DEEP DIVE / SOURCES → 次の興味**

とする。

**現代翻訳は入口、OWNER'S NOTEは接続、DEEP DIVE / SOURCESは根拠。**

## 3. 興味が出た瞬間にMATCHする

原則は **PUSHではなくMATCH**。

相手がモデル名を知っていることを待たない。相手がすでに持っている問い・違和感・好奇心へ、その文脈に合う実物を返す。

| 相手に出た興味 | 最初に渡す具体例 |
| --- | --- |
| 昔の通知 / 機械式リマインダー | 機械式アラーム腕時計というカテゴリ |
| 通知方法を切り替える古い機械 | Pierce Duofon |
| 同じアラームでも音が違う | HOW THEY RING / Cyma / Wittnauer |
| 高精度と複雑機構の矛盾 | Cyma Time-O-Vox Chronomètre |
| 最小構成・安価な機械の工夫 | Westclox Watchlarm / 0石 |
| 腕時計とは何かという境界 | Modern De Luxe等の分類問題 |

狙うのは「Pierce Duofon」と検索する人だけではない。

**興味 → 具体例 → 実物 / 音 / 資料 → もう一つの具体例**

へ変換する。

**興味がある人を追い回すのではなく、興味が表れた瞬間を逃さない。**

内部的には「同じ沼に落ちる素質を持つ人へ、最初の具体物を渡す」と捉える。

## 4. rabbit holeが成立したかの判定

次の流れが実測できた時に成立とする。

1. **DISCOVERY** — 時計や現象を外部で発見
2. **INTEREST** — 音・操作・問いへ反応
3. **ENTRY** — 該当ページへ到達
4. **DEPTH** — 実機・音・機構・資料まで進む
5. **NEXT INTEREST** — 関連WATCH / HOW THEY RING / HISTORY / 外部資料へ進む
6. **EVIDENCE ROUTE OPENED** — 以前はなかった証拠への経路が成立

PV増加だけでは成功としない。

既存のWATCH最下部やHOW THEY RINGへの導線がある場合、先に**使われたかを測る**。観測前に導線を増やさない。

## 5. 現在の作戦順序

### Phase A — EN / DEを全実装する

外部へ持ち出す前に、公開対象の多言語版を「存在する」ではなく**最後まで読める**状態にする。

対象:

- EN / DE TOP
- EN / DE HISTORY
- EN / DE OWNER'S NOTES一覧
- EN / DE HOW THEY RING
- 所有6 WATCHの EN / DE FULL RESEARCH
  - Basis Alarm
  - Pierce Duofon
  - Cyma Time-O-Vox
  - Citizen Alarm
  - Westclox Watchlarm
  - Wittnauer Cal.10WA
- 公開する独立研究ページ
  - Cyma Time-O-Vox Chronomètre

### Phase B — 翻訳の「完成度」を判定する

routeやファイルが存在するだけでは完成としない。

以下が揃った時だけ **LOCALIZATION READY**。

- 日本語正本の意味・構成・温度・断定度を保持
- OWNER'S NOTE / SPEC / DEEP DIVE / SOURCESの役割を保持
- 事実の追加・削除・編集的再構成がない
- 段落単位のcitation対応が維持
- 実機画像、音、操作ガイド、関連WATCHが欠落していない
- EN / DEの共有事実が localization-fact-sync と一致
- 既知の旧値が翻訳側だけ残っていない
- hreflang / sitemap / llms.txt / Analytics mappingが公開実体と一致
- build / localization coverage / localization sync / layout / live gateを通過
- ドイツ語は必要箇所で逆翻訳監査
- 英語は時計専門語と自然さを監査
- liveで最後まで読める

**IMPLEMENTED / VERIFIED / DEPLOYEDを混同しない。**

### Phase C — WATCHごとに外へ出せるか判定する

サイト全体を一括で「営業可能」としない。

1. **RESEARCH READY**
   - 本文 / 出典 / RESEARCH NOTE / REVISIONが現行
2. **LOCALIZATION READY**
   - 必要なEN / DEが完成・公開・同期済み
3. **OUTREACH READY**
   - 相手へ渡す一次資料 / 専門資料の該当箇所が特定済み
   - VAにしかない補完価値を1文で説明可能
   - 既知の誤り候補を未処理で残していない
   - 現行hostだけを使用
4. **CONTACTABLE**
   - 相手の現行ページ / 投稿ルール / 窓口を再確認済み
   - 相手の不足を何で補えるか具体化済み

%スコアは原則使わない。弱点を平均点で隠さないため、必要条件で判定する。

### Phase D — 1件ずつ外へ出す

最初からサイト全体を売り込まない。

初手は条件を満たした場合のみ **Watch Movements Archive / Cyma R.464 の1件**。

以降の順序は strategy/external-reference-outreach.md を正本とする。

## 6. 外部参照は「営業」ではなく資料補完

外部DB、Wiki、媒体、研究誌への接触でも主語は同じ。

**「うちのサイトを載せてください」ではなく「この資料・実機観察でここを補完できます」**とする。

評価状態:

**OUTREACH READY → CONTACTED → ACKNOWLEDGED → USED → LINKED → REFERRED VISIT → DISCOVERY EFFECT**

ただし最上位は LINKED ではなく **EVIDENCE ROUTE OPENED**。

相手側で資料が使われ、読者がより正しい情報へ近づけたなら、LINKがなくても成功になり得る。

「情報ください」は営業ではなく研究協力募集として使う。

- 欲しい情報を具体化
- 何が未確認かを明示
- 写真 / movement number / 広告 / parts list等、必要証拠を具体化
- 提供情報は確認前に事実化しない

閲覧者が資料提供者・実機提供者へ変わることも重要な成果とする。

## 7. 施策効果はファネルで見る

Discovery / SNS / Search:

**表示 → 反応 → Link Click → Entry Visit → Entry Page → Next Interest**

X側指標とCloudflare Visitsを1対1で同一視しない。

落ちた場合は、その層だけ直す。

1. 時計 / 現象が発見されたか
2. 興味反応があったか
3. リンクが押されたか
4. サイトへ到達したか
5. 狙ったページへ入ったか
6. 既存の次導線を使ったか
7. どこで落ちたか確認後に修正する

外部発見が弱いからといって、即座に本文量を増やさない。

## 8. 営業開始可能の最低条件

次を満たして初めて外部接触へ進む。

- EN / DE公開対象の全実装
- localization coverage / sync検証
- liveで主要言語導線を確認
- WATCHごとのRESEARCH READY判定
- 最初の営業対象1件がOUTREACH READY
- 先方の現行ページ / 窓口を接触直前に再確認
- 接触文の主語がサイト紹介ではなく、資料・観察結果になっている

## 9. 作戦を見直す条件

次の場合は再評価する。

- 多言語化でrevision driftが管理不能になる
- 外部接触でサイト宣伝と受け取られる事例が続く
- 外部資料へ実質的な補完価値を提供できていない
- SNSで興味反応はあるが、どの題材でもサイト到達が継続して成立しない
- 既存導線が十分表示されているのに、複数実験で回遊しない
- 外部研究者・コレクターから、より有効な資料共有経路が提示される

その場合もPVや被リンクを増やす方向へ自動で寄せず、**証拠へ辿れる経路を増やすという上位目的**から再設計する。
