# Research Image Evidence Custody — VINTAGE ALARM

この文書は研究判断に用いた画像の保全手順の単一正本。**研究証拠の記録先は既存の個体別Research Ledgerであり、新しい画像DBではない。** `PROJECT.md` → `AGENTS.md` → 分野別Ledgerの既存起動順を維持する。

## 判断画像の保全契約

**適用範囲**：実機同定、外観・ムーブメント比較、刻印、図版、特許図、販売画像、フォーラム添付、スクリーンショットなど、採用・保留・棄却を問わず研究判断の根拠に**実際に用いた画像**。単なる閲覧画像を無差別に収集しない。

1. **登録先は既存の個体別Research Ledger**。既存MapがあればCURRENT / OPEN / HOLD / 次の行動が変わる場合だけ更新する。新しい画像DB・重複CURRENT台帳を作らない。Ledgerが無い対象では既存の研究正本を確認し、勝手に新規Ledgerを生成しない。保存先が未確定ならHOLDを明示する。
2. 画像ごとに、再同定可能な**証拠ID**、対象WATCH / 判断項目、**何が画面に直接見えるか**、元資料の発言・記述と推論の別、元URL（投稿・出品・添付の直接URLを可能な限り併記）または書名・版・印刷ページ・PDFページ・図版番号、原ファイル名、確認日・取得日、取得主体を記録する。比較用画像は**別個体**と明示し、同一個体の証拠へ自動昇格しない。
3. バイトを実際に取得できた場合のみ**ファイルサイズとSHA-256**を計算・記録する。元画像とトリミング・補正・注釈画像は別ファイルとして対応付け、加工物を原本と呼ばない。未取得のハッシュや保存先を補完しない。
4. **保存状態は厳密に区別する**：`SOURCE_REFERENCED`＝URL・書誌・既存資料の位置だけ／`TEMPORARY_BYTES`＝この作業環境で実ファイルを取得したが永続性未検証／`DURABLE_VERIFIED`＝権限のある非公開等の永続保存先へ置き、後からそこから再読してバイト数・SHA-256一致を確認／`UNAVAILABLE_OR_HOLD`＝取得不能、保存権限未確認、保存先無し等。リンクやファイル名やSHA-256だけでは`DURABLE_VERIFIED`にしない。保存失敗・リンク切れ・再取得不能も隠さず残す。
5. **権利・公開状態は保存状態と独立**：本人撮影、第三者撮影、書籍・販売者画像、特許資料等の出典・権利状況と公開許可を区別する。許諾・利用条件が未確認なら公開GitHub / 公開VAへ画像ファイルや書籍ページを登録しない。私的保存の可否も個々の利用条件に従い、禁止される場合は書誌・URL・ページ参照だけ記録する。著作権資料の原PDFが既存Project / Libraryにあるならページを参照し、画像を再切出しして自動複製しない。
6. **保存場所の真偽を検証**：非公開の既存保存先（利用可能なLibrary・ユーザー管理領域等）を優先し、利用可否と権限を実際に確認する。期限付き作業フォルダや会話内添付の存在だけで、別チャットからの永続取得を保証しない。公開Ledgerには秘密・個人情報・共有トークン・プライベートURLを書かず、再参照用の安全な識別子と権限制約を記録する。
7. 研究回答・台帳更新の完了時に、判断に用いた画像の**登録件数／実ファイル取得件数／永続保存検証件数／未保存・HOLD件数**を確認する。保存先や権利が未確定でも研究判断そのものを捏造して止めず、「画像判断は可能／原本保全は未了」を分離して報告する。後日の回収は、元証拠との同一性を再確認してから保存状態を更新する。

**運用例（現時点の履歴を自動昇格しない）**：Wittnauer台帳の`IMG_5490.jpeg`等はファイル名・観察の記録だけで永続保存確認にはならない。ARSAの作業用`output/`画像とSHA-256も、それだけでは`TEMPORARY_BYTES`まで。専門書の該当画像はPDF原本＋ページを根拠として参照できるが、別の原画像アーカイブを作成したことにはならない。
