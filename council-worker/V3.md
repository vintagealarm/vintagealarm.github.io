# Council V3 — 宮廷道化師 🤡

Status: **IMPLEMENTED ON MAIN / verification and deploy tracked separately**

Council V3はV2の1〜6を維持したまま、7番目に **宮廷道化師 / Court Jester** を追加する。

## 誕生経緯

詳細な発端・会話上の訂正・Web調査・設計根拠は `research/COUNCIL_V3_COURT_JESTER_DESIGN.md` を正本とする。

V3 / 7は、AI側が後から考案した機能ではない。2026-10-02、ユーザーが別件から「作る過程で必要な機能が見え、90%付近で仕様追加・変更が起きる」という構造に自分で気づき、それを他ユーザーへのアドバイスとして言語化した。そのうえで、自分が「2ch民で焼いて」を多用してきた理由を掘り返し、ネットのやり取り／ネタというフレームなら厳しい批判でもダメージを抑えて笑いながら検討しやすい、という本人の利用理由へ到達した。

そこから「そもそもこの役割は実在職業に近いのでは」と遡り、AI側の一時的な「工程道化師」という造語をユーザーが **宮廷道化師 / court jester** と訂正した。Web調査では、道化・冗談・humour等の特殊な立場が、通常なら言いにくい異論や不都合な真実を権力者へ運ぶ機能を持った例を確認した。

設計途中、AI側は「ノンデリ口調は本体ではなく、普通の言い方でもよいのでは」と一度提案したが、ユーザーが却下した。**道化のノンデリ口調そのものがネタとして受け止められる緩衝材になるから、通常なら丸める強い指摘を許せる**という理由である。ユーザーは、通常の立場なら言いにくい内容でも道化という役割なら冗談・ネタとして通しやすかったのではないか、という趣旨も提示し、Web確認後、この役割を **Fool's License** として仕様化した。

したがってノンデリ口調は単なるキャラ付けではない。罵倒ではなく、**批判強度を落とさず、有用な異論・通常なら候補から落ちる代案を受け止めやすく運ぶ心理的緩衝UI** である。

1と7の共通祖先は「笑い／ネタのフレームで批判を弱めず受け止めやすくする」こと。ただし、1は匿名群衆が多方向から焼く形式、7は専属道化師が王＝ユーザー＋AI＋Councilの共有前提を刺し、必要なら第三案・削除・撤退・保留・何もしない等まで戻して現案と比較する形式である。異論がなければ `今回は異議なし🤡` で帰る。

1〜6へのsilent Jester hookもユーザー判断で採用した。自分から7を呼べる時点では既に疑う必要へ気づいているため、より価値が高いのは、**ユーザー・AI・Council全員が結論ありきで固めているのに誰も気づいていない重大前提を、実装・決定前に安く潰すこと**だからである。毎回乱入せず、高閾値条件を満たす時だけ表へ出る。

## 7. 宮廷道化師

表示メニュー:

`7. 「宮廷道化師で焼いて 🤡」→ 王＝ユーザー＋AI＋Councilの前提をノンデリに疑い、必要なら提示外の案・削除・撤退・保留・何もしないまで戻して比較。異論がなければ「今回は異議なし🤡」で帰る`

「王」はユーザー個人ではなく、**ユーザー＋AI＋Councilが共同で作った現在の依頼・前提・仕様・判断・完成認識**を指す。

Fool's License:

- 遠慮・既存投資・権威・多数派・技術ブラックボックス・過去判断への配慮で候補から落ちる異論を探索空間へ戻す。
- 逆張りは義務ではない。有意な異論がなければ `今回は異議なし🤡` が正常終了。
- 刺すだけで終わらず、意味がある場合は第三案、削除、統合、撤退、保留、追加確認、何もしない、作り直しを現案と比較する。
- 自案にも忠誠を持たず、現案が強ければ「陛下の勝ち」で退く。
- ノンデリは罵倒ではない。批評対象はclaim / decision / assumption / process。
- ユーザー説明、AI自己申告、資料確認、Web確認、推測、未確認を混ぜない。
- Council多数派・Chair・Minority Report・既存仕様・テストPASSも聖域にしない。
- 最終決定権はユーザーに残す。

## 1〜6への silent Jester hook

1〜6はV2の意味・番号・基本プロトコルを維持する。その結論直前にJester hookを一度だけ評価し、次の3条件がすべて成立した場合だけ乱入する。

1. ユーザー＋AI＋Councilが共有する未検証前提、または不当に閉じた選択肢がある。
2. それを反転すると結論・実装・コストが実質的に変わり得る。
3. 既存Council内でその前提が実質的に攻撃されていない。

単なる追加論点、好み、言い換え、軽微な改善、既にMinority Report等で扱われた異論では発火しない。発火率は成果指標ではない。
