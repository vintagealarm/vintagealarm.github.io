# 2. 評価フレーム — 物差し

REGALIA研究で作った以下を流用する。

**総合購入価値 = 製品価値 + 取引価値 - 代替機会費用 - 長期拘束コスト**

今回の「50,000円枠」では、さらに次を重視する。

## 2-1. 死に金率

その商品をキャンペーンがなくても近い将来に買った可能性。

- 高い → 良い
- キャンペーンがなければ絶対買わない → 弱い

## 2-2. 差額利用率

既存品に対して追加された機能・性能のうち、本人が実際に使う割合。

例:
- 初代ReFa → 最新ReFaで同じファインバブル機能の豪華版: 差額利用率が低い可能性
- 初代ReFa → 別機構を追加するMYTREX +e: 機能差は明確

## 2-3. 用途複線化

1用途だけではなく複数の独立用途を持つか。

例:
- ポータブル電源: 防災 + キャンプ + 移動電源
- iPhone Pro: 日常端末 + 時計撮影 + SNS + VINTAGE ALARM素材作成 + ローカル保存

## 2-4. 置換型 > 純増型

既存の不満品を置換するものは、物を増やすだけの商品より強い。

## 2-5. 将来支出の前倒し

1〜3年以内にどうせ買う物を、今回の条件へ同期できるなら強い。

## 2-6. 取引条件と商品価値を混ぜない

無金利・ポイント・割引は「商品が良い理由」ではない。

- まず総額の商品として欲しいかを判定
- その後に0%分割等を資金管理手段として評価

## 7-4. 512GB vs 1TB

現時点の仮説:

### 256GB
- 従来の2年返却型なら合理的
- 長期所有 / ローカル保存方針では余裕が小さめ

### 512GB
**現在の本命。**

理由:
- 現在112.06GBをそのまま移しても約400GB余白
- 初Proで写真 / Pro系撮影データが増える余地
- 本体ローカル保存志向
- 3〜5年利用または後年の撮影機転用に余裕
- 256→512差額は35,000円

### 1TB
現時点では弱い。

- 512→1TB差額が70,000円
- 現在の使用量だけでは512GBを超える証拠がない
- 大容量プレミアムは中古売却時に全額回収しにくい
- 「長く使うから」だけでは正当化しない

1TBを復活させる条件:
- 512GBを3〜5年以内に超える具体的なデータ生成量が見える
- 大量ProRAW / ローカル動画 / オフライン資料等を実際に常時持つ運用になる
- クラウド / 外部ストレージへ逃がさない価値が70,000円以上ある

# 24. 所有・導入済みゲート — 候補提示前に必ず照合

2026-09-22、候補探索で**既所有の防湿庫を未所有候補として提示する誤り**が発生した。
原因は、商品発散を先に行い、所有・導入済み・購入確定・売却済み・検討済みの照合を候補生成後へ回したこと。

以後、この探索では商品検索より前に次の状態を区別する。

- **OWNED** — 現在所有 / 使用中。原則として同種商品の新規候補から除外する
- **PURCHASED / COMMITTED** — 購入確定・契約済み。重複購入を避ける
- **APPLIED / PENDING** — 応募・入手待ち等。結果次第で重複するため候補には警告を付ける
- **SOLD / EXITED** — 売却・返却済み。現所有と混同しない
- **CONSIDERED / REJECTED** — 検討済み / 棄却済み。新しい根拠なしに復活させない
- **UNKNOWN** — 所有有無を確認できない。所有していないと推定しない

## 24-2. 候補生成の必須順序

今後の5万円発見隊は必ず次の順序で行う。

1. この台帳の所有・導入状態を読む
2. 現在会話で新しく判明した所有品 / 購入品 / 売却品を反映
3. 必要なら関連する過去文脈を確認
4. **既所有品・購入確定品・応募中で重複するカテゴリを除外 / 保留**
5. その後に初めて商品カテゴリを発散する
6. 発散後、「買った翌日に今まで出来なかった動詞が増えるか」で一次選別
7. 実摩擦、使用頻度、設置、メンテ、消耗品、出口価値で反証
8. 生き残った候補だけヤマダ現行取扱い・価格をWeb確認
9. **Web掲載とLABI池袋店頭在庫を混同しない**
10. 所有有無が不明な候補は、未所有前提で推薦せず UNKNOWN と明示する

## 24-3. 探索原則の追加

- 「既に持っている物の高級版」は、具体的不満や能力差が確認できない限り候補から落とす
- 所有品を忘れた状態で「徹底探索済み」と報告しない
- 過去会話 / GitHubに証拠がない所有状態を捏造しない
- 不明は不明のまま保持する
- 候補数を増やすために弱い案を残さない
- 途中工程を完成品としてユーザーへ返さない
- Council 5を使う場合も、**所有ゲート通過後にBrainstorming Boardを開始する**
