# WATCH research metadata policy

`src/data/watch-research/` は、WATCH記事の完成度を採点する場所ではない。  
公開記事とは別に、**継続中の調査状態・採択判断・未解決事項・改訂履歴を保持する必要がある個体だけ**を登録する。

## 1. 位置づけ

- WATCH本文の正本は `src/content/watches/`。
- 参考資料・出典の正本は各WATCHの `sourceMeta` / `sources`。
- 掲載個体の観察・実測は、公開本文で必要なものはWATCH側へ記載する。
- `watch-research` は、公開本文を置き換えるDBではなく、**研究過程の補助台帳**。
- `watch-research` の有無を、記事品質・調査量・重要度・完成度のランキングに使わない。

現在、Cyma Time-O-Vox と Pierce Duofon に専用台帳がある。  
Basis Alarm / Citizen Alarm / Westclox Watchlarm / Wittnauer Cal.10WA に専用台帳がないことは、記事や調査が未完成という意味ではない。

## 2. 台帳を作る条件

次のいずれかがあり、**今後も判断・更新が動く可能性がある場合**にだけ作る。

- 複数資料が食い違い、現行採択と保留理由を継続管理する必要がある。
- 一次資料未確認など、明示的な未解決事項が残る。
- 実測 `n=1` と文献値の差を継続観察する。
- 「どの説を現在採るか」が本文だけでは追いにくく、判断理由を残す必要がある。
- 訂正・再調査が複数回発生し、改訂履歴そのものに意味がある。
- 購入書類・個体資料など、研究状態を示す補助証拠の確認状況を継続管理する。

単に次の理由だけでは作らない。

- 記事が長い。
- 出典数が多い。
- 珍しい時計である。
- OWNER OBSERVATIONがある。
- DEEP DIVEが充実している。
- 他のWATCHにも台帳があるので形式を揃えたい。

**空の台帳を均一化目的で先に作らない。**

## 3. 二重管理を避ける

台帳へ、WATCH本文・出典一覧をそのまま複製しない。

### WATCH側に置くもの

- 公開する確定事実
- 読者に必要な資料差
- 掲載個体の観察・実測
- DEEP DIVEで扱う機構・変遷・文献差
- `sourceMeta` / `sources`

### watch-research側に置くもの

- 研究状態の要約
- 現在の採択判断
- 未解決事項
- 追加確認が必要な点
- 重要な訂正・再評価の履歴

同じ文章を両方へ保存しない。  
台帳は「本文のコピー」ではなく、**なぜ現在その記述・保留状態になっているかを追跡するための記録**とする。

## 4. 公開表示との関係

研究メタデータがあるWATCHでは、既存仕様どおり参考資料・出典details内に

`SOURCES → RESEARCH NOTE → REVISION`

の順で表示できる。

研究メタデータがないWATCHへ、空の `RESEARCH NOTE` / `REVISION` を出さない。

台帳を追加すること自体を理由に、

- OWNER'S NOTE
- 確定済みキャッチ
- WATCH本文
- DEEP DIVE
- レイアウト

を変更しない。

## 5. ライフサイクル

### 作成

上の作成条件を満たし、継続管理の価値がある時だけ追加する。

### 更新

次の場合に更新する。

- 新しい一次資料・専門資料を確認した。
- 実測・掲載個体観察が追加された。
- 採択判断が変わった。
- 未解決事項が解決した、または新しく増えた。
- 公開本文を事実関係の理由で訂正した。

### 解決後

未解決事項が解決しても、**改訂履歴そのものに意味がある場合は台帳を残してよい**。  
「全WATCHを同じ形に揃える」ために削除・追加しない。

台帳の内容が完全に安定し、本文・Git履歴だけで十分に追跡でき、補助台帳としての価値がなくなった場合だけ統合・削除を検討する。削除は自動化しない。

## 6. 現行登録

実装上の登録正本は `src/data/watch-research.ts`。

現時点の登録:

- `cyma-time-o-vox`
- `pierce-duofon`

このリストは研究台帳の登録状況であり、公開WATCH一覧・品質一覧ではない。

## 7. 新規登録時の確認

1. WATCH本文だけでは追いにくい「動く研究状態」が本当にあるか。
2. 既存の `sourceMeta` / `sources` / 本文と重複しないか。
3. `summary` は現在状態、`revisions` は重要な変更履歴として分離できているか。
4. 台帳追加だけを理由に承認済み本文を変更していないか。
5. 研究メタデータなしのWATCHへ空表示が漏れていないか。

目的は形式統一ではなく、**必要な個体だけ研究判断を再現可能にすること**。
